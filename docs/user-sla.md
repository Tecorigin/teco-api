# 用户 SLA 统计

Dashboard 的“用户 SLA 统计”位于“模型 SLA 统计”之后，仅管理员可见。两个页面共享筛选、排序和表格布局，均从主数据库的窗口汇总读取数据。

## 数据口径

- `sla_results` 保存每次尝试（`mode=model`）和最终结果（`mode=user`），包括平台内部请求 ID、客户端请求 ID、用户、模型、渠道、起止时间和尝试序号。最终记录的 `attempt` 表示实际尝试次数。
- `sla_buckets` 保存按模式、用户、模型和 5 分钟窗口聚合的总数及失败数，使用模式和时间联合索引查询。
- 明细插入和汇总增量在同一个主库事务中完成；事件唯一键保证重复提交不会重复计数。客户端重复使用请求 ID 不会合并不同请求。
- 普通 Relay 和异步任务提交 Relay 均采集；每次实际进入转发的调用保存尝试结果，函数退出时保存最终结果。
- 模型 SLA 保留重试前失败，按每次尝试结束时间归属窗口；用户 SLA 只统计已结束请求，按进入 Relay 的时间归属窗口。正在重试的请求尚未进入用户汇总。
- 转发前的限流、渠道选择等失败只进入用户最终结果，不生成不存在的上游尝试；必须具备用户名和原始模型名才能采集。
- 异步任务只统计提交结果，不表示后台任务最终完成；Midjourney 独立处理入口和未进入 Relay 的中间件拒绝暂未采集。
- 成功取决于转发处理函数返回无错误，而不是消费日志是否存在。
- SLA 明细和汇总由主数据库迁移创建，支持 SQLite、MySQL 和 PostgreSQL，与日志数据库类型无关。
- 当前采用同步事务写入，每次尝试及最终结果各执行一次事务；失败只输出关联请求的错误日志，不改变转发结果、不自动重试。数据库不可用或进程异常退出仍可能丢失统计，暂不提供持久化队列。
- 首次部署从新流量开始采集；历史日志不自动回填，查询不回退到日志表。长时间范围返回的是已有采集数据，不代表部署前完整历史。

## 窗口与公式

沿用现有模型 SLA 的 5 分钟窗口及时间边界处理。总窗口数仅统计有请求的窗口。窗口内去重后总请求数至少为 5 且存在失败请求时，才计为错误窗口。

`SLA = (1 - 错误窗口数 / 总窗口数) × 100%`

API：`GET /api/perf-metrics/model-sla?mode=user`，保留现有管理员鉴权。省略 `mode` 或使用 `mode=model` 时返回尝试口径的模型 SLA。
